## Existing game boundary and independent proof

- `frontend/features/games/GameLoader.ts` explicitly lazy-imports `@funkspace/wave-survivor`. `GameHost.tsx` owns Canvas/viewport refs, load cancellation, theme subscription, visibility listener and controller destruction. It currently auto-starts, calls resume on visibility return, and ignores wave-cleared, upgrade and result events. Those are baseline behaviors, not EPIC 7 acceptance.
- `frontend/features/games/theme/FunkSpaceGameThemeAdapter.ts` converts ThemeService state to immutable resolved semantic `GameTheme` values. Game code does not import frontend private code, ThemeService, DOM theme attributes or portfolio CSS variables.
- `games/wave-survivor/src/index.ts` exports `createGame`, `GameController`, mount/theme/status/event/result types. Controller methods include `start`, `pause`, `resume`, `restart`, `chooseUpgrade`, `setTheme` and terminal/idempotent `destroy`. `onEvent` already exists; the proposed `reducedEffects` input is absent. Consolidate duplicated host types only after auditing the existing contract.
- The package owns the game loop, simulation, input and Canvas rendering. The renderer handles portrait fit and observer cleanup; frontend unmount removes listeners/subscriptions and destroys the controller. React receives discrete status/events, not per-frame engine state. The standalone demo remains independently runnable.
